1. Overview

This document specifies the exact actions, intervals, and repetition counts needed for each of the 4 users (Amal, Manasa, Dristi, Vyas) to generate sufficient behavioral biometric data for training the LightGBM classifier and One-Class SVM anomaly detector.

Data Collection Mechanism

Component Detail
Collector BehavioralCollector — captures keystroke + mouse dynamics in 5-second windows
Storage localStorage key ag_behavioral_dataset (when VITE_BEHAVIORAL_EXPORT=true)
Export JSON download via BehavioralExportPanel component
Features 14 numerical features per 5-second window (see below)

14 Features Per Window

dwellMeanMs   dwellStdMs   flightMeanMs   flightStdMs   keysPerSec
velocityMean  velocityStd  accelerationMean  accelerationStd
curvatureMean curvatureStd  clickCount  scrollAmount  mouseTravelPx

What is a "Window"?

A window is a 5-second slice of your activity. Every 5 seconds, the BehavioralCollector running in the browser takes a snapshot of everything you did during that interval and computes 14 numerical values from it.

Think of it like a heart-rate monitor for your typing and mouse behavior — instead of beats per minute, it captures things like how long you held each key, how fast you moved the mouse, how many times you clicked, and how much you scrolled.

Example: If you spend 5 minutes browsing the dashboard, that generates roughly 60 windows (5 min × 60 sec ÷ 5 sec per window). Each window is one row in the training dataset — a single labeled data point the ML model learns from.

How the numbers translate to real activity:

If you are... The window will show...
Typing your email & password High dwellMeanMs, high keysPerSec, low mouse values
Moving the mouse across the dashboard High velocityMean, high mouseTravelPx, no keystroke values
Scrolling through transactions High scrollAmount, moderate mouse travel, no keystrokes
Idle (reading a page) All values near zero — these get filtered out during training
Filling a transfer form Mix of keystroke features (typing amount) + mouse features (selecting beneficiary)

Why 800–1,200 windows per user?

Machine learning models need enough examples to learn what makes your behavior unique. With 14 features per window:

  • OC-SVM (unsupervised) needs ~500+ windows of only your genuine behavior to build a reliable boundary of "normal"
  • LightGBM (supervised) needs both genuine and impostor examples — at least 800 genuine + 200 impostor per user to achieve 85%+ accuracy
  • More windows = the model sees more variety (different times of day, different tasks, different moods) = more robust detection

3. Phase 1: Genuine User Profile (Days 1–7)

Each user collects their OWN behavioral data. These sessions are labeled genuine.

Session A — Login & Dashboard Browsing

⏱ ~5 min  |  📊 ~50 windows  |  🔁 2× per day (morning + evening)
  1. Navigate to login page, type email (natural pace)
  2. Type password, click login
  3. Wait for dashboard to load, scroll through all widgets
  4. Move mouse across dashboard cards (balance hero, Aegis widget, security overview, transaction feed)
  5. Hover over chart tooltips in trends/analytics
  6. Click through each tab/section slowly

Captured: Keystroke dynamics (email + password typing), mouse velocity/curvature during navigation, scroll patterns, click patterns

Session B — Transaction Feed & Account Exploration

⏱ ~7 min  |  📊 ~70 windows  |  🔁 1× per day
  1. Login (natural typing)
  2. Navigate to Accounts page — click each account card
  3. View transaction history — scroll through 20–30 transactions
  4. Click on 3–5 individual transactions to view details
  5. Switch between account filters (All / Checking / Savings)
  6. Type in transaction search bar (3–4 different queries: "Amazon", "Uber", "salary")
  7. Sort transactions by date, amount — click sort toggles

Captured: Keystroke for search queries, mouse movement for navigation, click cadence, scroll velocity

Session C — Transfer Flow

⏱ ~5 min  |  📊 ~50 windows  |  🔁 2× per day
  1. Login
  2. Navigate to Transfer page
  3. Type an amount in the transfer field (vary amounts: $25, $100, $250, $500, $1000)
  4. Select a beneficiary from dropdown — scroll through list
  5. Type a reference note (vary: "rent payment", "dinner", "utilities", "gift")
  6. Press-and-hold the transfer button (triggering the PressHoldButton component)
  7. Wait for confirmation screen

Captured: Keystroke for amount/reference typing, mouse for dropdown selection, press-and-hold button pressure timing

Session D — Beneficiary & Card Management

⏱ ~4 min  |  📊 ~40 windows  |  🔁 1× per day
  1. Login
  2. Navigate to Beneficiaries page — scroll through list
  3. Add a new beneficiary: type name (3 variations per user), IBAN, select bank
  4. Navigate to Cards page — view all cards
  5. Freeze and unfreeze a card
  6. View card limits and spending details

Captured: Form-filling keystroke patterns, mouse precision during small-target clicks, scroll behavior

Session E — Budgets & Savings

⏱ ~5 min  |  📊 ~50 windows  |  🔁 1× per day
  1. Login
  2. Navigate to Budgets page — scroll through all categories
  3. Click each budget category to view breakdown
  4. Create a new budget envelope (category + amount)
  5. Navigate to Savings Goals page
  6. Update savings goal progress (add $50–$200)
  7. Scroll through goal details

Captured: Keystroke for budget amounts/goal updates, mouse movement patterns, scroll depth

Session F — Statement & History Review

⏱ ~6 min  |  📊 ~60 windows  |  🔁 Every other day
  1. Login
  2. Navigate to Statements page
  3. Select different months from the dropdown
  4. Scroll through monthly statements
  5. Export/download a statement
  6. Navigate to Activity page
  7. Scroll through activity feed — click to expand details
  8. Filter activity by type

Captured: Menu navigation mouse patterns, scroll behavior on long lists, click targeting precision

Session G — Rapid Navigation

⏱ ~3 min  |  📊 ~30 windows  |  🔁 1× per day
  1. Login
  2. Rapidly switch between all main pages (Dashboard → Accounts → Transfers → Cards → Budgets → Savings → Activity → Statements)
  3. Click through each page but don't interact deeply
  4. Logout

Captured: Fast mouse movement patterns, quick click cadence, minimal keystroke (just login)

Impostor Session Protocol (~5 min each, ~50 windows)

8. ML Training Pipeline (After Collection)

Step Action
1 Load all JSON files into pandas DataFrame
2 Filter: Remove windows with <3 keystrokes AND <50px mouse travel (idle windows)
3 Normalize: Z-score normalize features per user
4 Feature selection: Run mRMR to select top discriminative features
5 Train OC-SVM: On genuine-only data, RBF kernel, nu=0.05
6 Train LightGBM: Binary classifier on labeled genuine+impostor data
7 Evaluate: AUC-ROC target > 0.90, accuracy target > 85%
8 Export models: Save as .joblib files to MinIO/S3

Model Architecture

LightGBM Classifier ("The Discriminator")

Supervised binary classifier: genuine vs impostor. Output: probability score P(legitimate) ∈ [0, 1]. Reference accuracy: ~94.68% (literature), project target: 85%+, AUC-ROC > 0.90.

One-Class SVM ("The Gatekeeper")

Unsupervised novelty detector trained ONLY on genuine user data. RBF kernel, nu=0.05. Trained per-user (each user has their own "normal" behavioral boundary).

Score Fusion

fused = 0.6 × LightGBM + 0.4 × (1 − OC-SVM_norm)

Decision thresholds: Allow ≥ 0.85  |  Warn 0.60–0.85  |  Challenge < 0.60
