Auth Flow (4 pages)

1. Identity Screen

/auth/

The gate — adaptive login-or-register in a single form.

Sections
Email input — client-side validation with live feedback (valid/invalid states). Auto-derives display name from email local-part.
Password input — minimum 12 characters enforced. Shows "Must be at least 12 characters" hint when too short.
Submit button — tries LOGIN first. If that fails (user doesn't exist), falls through to REGISTER. If register succeeds, navigates to OTP verification.
Enterprise SSO button — placeholder for SAML/OIDC integration.
Preview panel — decorative balance tiles and transaction rows (marketing, not real data).
Combining login and register behind one button eliminates the "do I have an account?" friction. The button does the right thing automatically. Password minimum is enforced client-side to avoid a confusing 422 from the backend.

2. OTP Verification

/auth/verify

6-digit one-time password entry after registration.

Sections
OTP Pucks — 6 animated input circles that glow in sequence as digits are entered. Visual feedback per digit.
Resend timer — countdown before re-request (currently static "0:45").
Device memo — "This device has not been seen before — we'll remember it."
Calibration transition — spinner + "Code accepted. Calibrating your behavioral profile…" on success.
Error hint — if OTP fails, suggests checking the backend terminal for the code.
OTP proves device/channel ownership before creating the account. The backend stores codes in Redis (5-minute TTL) and logs them to console — no SMTP integration yet. This will eventually send via email/SMS.

3. Behavioral Calibration (Enrollment)

/auth/calibrate

Captures keystroke and mouse dynamics to build a behavioral baseline.

Sections
Typing sample — prompts user to type a passphrase. Captures hold times (ms per key press) and flight times (ms between keys) — 10 features each.
Mouse sample — prompts mouse movement. Captures velocity profile (5 features), curvature profile (5 features), and jerk profile (5 features).
Progress bar — shows enrollment progress through both phases.
Completion screen — shows baseline quality score (0-1 confidence) and navigates to signature page.
This is the AI enrollment phase. The behavioral biometric data is sent to the backend POST /auth/enrollment endpoint. Currently processed by a mock scoring service — will be replaced by the real Behavioral Authentication engine (LightGBM + One-Class SVM) in the AI phase.

4. Behavioral Signature

/auth/signature

Displays the user's unique behavioral signature glyph and redirects to the app.

Sections
SignatureGlyph — a unique geometric pattern derived from the user's enrollment data (hash-based visual fingerprint). Each user sees a different glyph.
Auto-redirect — after a brief animation, navigates to /app.
Builds trust — the user sees a visual confirmation that their behavioral profile was captured. The glyph is deterministic from a hash seed, so it stays consistent across sessions.

Banking App — Main Dashboard & All Pages

5. Dashboard

/app/

The command center — every banking widget and security metric on one screen.

Sections (top to bottom)
CommandBar — global search input, Aegis confidence pill (live), notification bell (unread count), quick-transfer button, current time, avatar/SignatureGlyph. Sticky header that gains a backdrop-blur on scroll.
Persistent chrome. The confidence pill and notification bell give at-a-glance security status without navigating away. The avatar glyph is the user's behavioral signature — subtly reinforcing "the system knows it's you."
WelcomeHeader — greets user by display name, shows date, and displays 3 stat chips (accounts count, total transactions, active savings goals) — computed from real hook data.
Warm greeting with contextual stats. Uses real data from useAccounts() and useTransactions().
BalanceHero — the main balance card showing selected account's balance (€/$, large 56px font), delta percentage, account switcher dropdown, IBAN, pending amount, and a mini area chart (HeroChart). Has hide/reveal toggle and action buttons (Transfer, Deposit, Pay, Exchange, Statement). Falls back to "No accounts available" if empty.
The most prominent financial element. The account switcher lets users flip between checking/savings/investment/business accounts. The hero chart is decorative but follows a positive trend to convey growth visually.
AegisWidget — 6-row security card: Confidence ring (live %), Trust level (computed from confidence), Active Sessions count, Device Trust, Behavioral Match, Risk Score. Also shows Whisper text — a natural-language security note from the backend.
Brings security transparency to the dashboard. Every metric is live from useAegisSnapshot() and useSecurityOverview(). No hardcoded values. The whisper text will eventually be AI-generated explanations.
SecurityOverview — 7-card grid: Auth Confidence, Trusted Device, Active Sessions, Flagged Events (24h), Session Integrity (grade), AI Monitoring (status), Risk Assessment (computed). Each card has a label, value, and descriptive note.
Quick security posture snapshot. The 7 dimensions mirror real security operations: who, what device, how many sessions, any flags, session quality, AI status, and risk level.
WidgetMosaic — 7 self-contained sub-widgets:
  • InsightsCard — AI-generated financial insights (e.g. "Spending increased 12%", "Subscription overlap detected"). Shows tone icon (up/down/saving/shield/growth), title, body, and action button.
  • SpendDonut — donut chart of spending by category (Housing, Groceries, Transport, etc.) with total and category breakdown. Uses useBudgets() + useDashboardAnalytics().
  • CashFlow — income vs. expense visualization with totals. Uses useDashboardAnalytics().
  • SavingsGoalWidget — first savings goal progress bar (e.g. "Vacation Fund: 67.5%"). Uses useSavingsGoals().
  • PortfolioCard — total portfolio value, allocation breakdown by holding, day change %. Uses useHoldings().
  • FxCard — live exchange rates (USD, EUR, GBP, JPY, CHF, CAD, AUD, INR). Uses useCurrencies().
  • BeneficiariesCard — top favorite beneficiaries with initials and last-used info. Uses useBeneficiaries().
Each sub-widget is independently data-fetching via its own React Query hook. No data flows through props — each component calls its hook internally. This means widgets can be rearranged or extracted without breaking data flow. Loading skeletons, empty states, and error boundaries guard every widget.
TransactionFeed — list of recent transactions with description, amount, currency, category, date, and status (completed/pending). Pulls from useTransactions().
Quick transaction review without navigating to the full transactions page. Uses real MongoDB data seeded on first access.
AttentionLane — alert-style notifications (e.g. "Unrecognized login attempt", "Large transfer pending"). Currently uses a static seed — will be driven by the AI anomaly detection pipeline.
Security alerts where users need them — on the dashboard. Future: AI-generated anomaly notifications from the behavioral engine.
ActionDock — 6 quick-action shortcuts at the bottom: Transfer, Pay, Deposit, Exchange, Statement, Investments. Always visible, no scrolling needed.
Reduces clicks for frequent actions. Mobile-friendly persistent toolbar.

6. Accounts List

/app/accounts

All bank accounts with balances, types, and IBANs.

AccountCard per account — name, balance (with hide/reveal), type (primary/savings/investment/business), currency, IBAN, delta %, sparkline mini-chart. Links to detail view.
Full account overview. Uses useAccounts() — data from MongoDB via seed-on-first-access pattern.

7. Account Detail

/app/accounts/$id

Deep view of a single account with all transactions.

BalanceHero for that account + filtered TransactionFeed showing only that account's transactions. Uses useAccount(id) and filtered useTransactions({ accountId: id }).
Transaction history filtered by account. The dynamic route parameter drives the data fetching.

8. Bank Cards

/app/cards

All debit/credit/virtual cards with limits and spending.

BankCard / CardObject — card visual with network logo (Visa/Mastercard), last 4 digits, holder name, expiry, frozen status, finish style (platinum/champagne/iris), daily/monthly/ATM limits, spending progress. Uses useCards().
Card management overview. The card object component renders a realistic card visual with finish gradients.

9. Money Transfer

/app/transfer

Initiate a transfer to a beneficiary.

Form — from account selector, beneficiary selector, amount input, currency, reference field. PressHoldButton — requires press-and-hold to confirm (prevents accidental transfers). Uses useInitiateTransfer() mutation.
The press-and-hold confirmation is a behavioral security measure — it's harder to trigger accidentally or via script. Transfer invalidates account and transaction caches on success.

10. Transactions

/app/transactions

Full transaction history with search and filter.

TransactionRow list — description, amount (color-coded credit/debit), currency, category, date, status, beneficiary, reference. Uses useTransactions() — 50 most recent from MongoDB.
Complete financial history. Transaction data is deterministic per user (seeded from user_id hash), so it's consistent across sessions.

11. Scheduled Payments

/app/payments

Recurring payments — rent, insurance, subscriptions.

List of ScheduledPayment entries: description, amount, currency, next date, frequency (monthly/quarterly), beneficiary. Uses usePayments().
Forward-looking cash flow visibility. Helps users plan around recurring obligations.

12. Beneficiaries

/app/beneficiaries

Saved payees for transfers.

List of BeneficiaryCard items: name, IBAN, bank, currency, favorites indicator. Uses useBeneficiaries(). New beneficiaries can be added via a form.
Transfer recipients management. Beneficiaries are stored in MongoDB and linked to transfers.

13. Statements

/app/statements

Monthly bank statements with year/month navigation.

Year/month picker — select a year (current year - 2 through current) and month. Statement view — opening balance, closing balance, list of transactions for that month. Uses useStatementYears() and useStatement({ year, month }).
Traditional bank statement format for reconciliation and record-keeping. Data is computed from transaction history.

14. Investments / Portfolio

/app/investments

Portfolio holdings with performance metrics.

List of Holding entries: symbol, name, quantity, price, total value, currency, delta %. Total portfolio value at top. Uses useHoldings().
Portfolio tracking. Holdings seeded per-user (AAPL, VTI, BTC, SPY, GOOGL) with realistic prices and jitter.

15. Savings Goals

/app/savings

Goal-based savings tracker.

List of SavingsGoal entries: name, target amount, current amount, progress %, deadline, image (beach/car/shield). Includes progress bars. Uses useSavingsGoals().
Goal-oriented savings psychology — visualizing progress toward a named goal increases motivation and retention.

16. Budgets

/app/budgets

Category-based budget envelopes with spending tracking.

List of BudgetEnvelope entries: category (Housing, Groceries, Transport, Dining, Entertainment, Utilities, Shopping, Healthcare), budgeted amount, spent amount, remaining %, color-coded progress bars, currency. Uses useBudgets().
Envelope budgeting method — allocate money to categories and track spending against each envelope. Color coding gives visual spending health at a glance.

17. Loans

/app/loans

Active loans with repayment tracking.

List of LoanRecord entries: name (Home Mortgage, Auto Loan), principal, remaining, currency, interest rate %, next payment date, progress bar (paid vs remaining). Uses useLoans().
Debt visibility. Shows both the remaining amount and how close the loan is to being paid off.

18. Foreign Exchange

/app/exchange

Live currency exchange rates.

Grid of Currency entries: code, name, rate (vs USD), symbol. 8 currencies: USD, EUR, GBP, JPY, CHF, CAD, AUD, INR. Uses useCurrencies(). Global data — same for all users.
Quick FX reference for international banking. Rates have micro-jitter to simulate live fluctuation.

19. AI Insights

/app/insights

AI-generated financial recommendations and alerts.

List of InsightCard items: tone icon (up=spending increase, down=subscription alert, saving=goal progress, shield=security, calendar=upcoming payment, growth=portfolio gain), title, body text, action button. Uses useInsights().
Actionable financial intelligence. Each insight has a clear tone (emotional valence) and a specific action. Future: AI-generated from transaction patterns.

20. Activity Log

/app/activity

Audit trail of user actions.

List of ActivityEvent entries: type (login/transfer/beneficiary_added/card_frozen/statement_viewed), description, timestamp. Uses useActivity().
Transparency — users can see every action taken on their account. Builds trust and aids security investigation.

The 6 identity factors create a multi-dimensional trust model. The behavior mosaic cards are the primary visualization surfaces for the AI engine (Feature Extraction, LightGBM, One-Class SVM, SHAP).

33. Admin Cockpit — Pulse Dashboard

/admin/

Real-time operations dashboard for the behavioral authentication platform.

Admin Cockpit Deep Dive — Every Section Explained

A. Hero Header

Today's overview — date stamp (e.g. "Sun 28 Jun") with monospace styling.
Title: "Cockpit" — signals this is the ops/engineering view.
Stat line — "Behavioral biometrics in production · 124,891 enrolled users · model v2.4.1".
Live indicator — pulsing green dot + "aegis online · 1.24k predictions/s".
Establishes the admin as an operational dashboard (not a marketing page). The enrolled user count and model version establish scale and versioning awareness. The predictions/s metric shows inference throughput.

B. KPI Grid (4 MetricCells)

4 key performance indicators fetched from useAdminKpis():
  • Active Users — current 24h active user count with delta and sparkline
  • Auth Success Rate — % of authentications that passed (no challenge)
  • Avg Confidence — mean behavioral confidence across all active sessions
  • Flagged Sessions — sessions currently in warning/critical status
Each KPI shows value, suffix, delta %, signal color (green/yellow/red), and a mini sparkline.
Executive summary in 4 numbers. The signal color gives instant health assessment. The sparkline shows the trend — is it getting better or worse? These are the metrics an operations team watches on a wall monitor.

C. Confidence River

RiverChart — a 901-point time series of authentication confidence over the last 24 hours. Height: 180px. Pinned events at specific indices: watch (yellow), alert (orange), critical (red), ok (green). Header shows min/max range and "stable" status.
The river chart is the tactical heartbeat of the platform. A sudden dip in confidence across all users could indicate a system-wide issue (model degradation, data pipeline failure). The pins mark incident timestamps for correlation.

D. Live Sessions Table

LiveTape — real-time table of the 8 most recent active sessions. Columns: User (with initials avatar), Page (current route), Confidence % (with SignalDot color), Risk score (numeric, red if > 0.5), Activity (what they're doing), Last event timestamp. Fetched from useAdminLiveSessions().
Like an air-traffic control radar — see every active user, their confidence level, and risk score in real time. Operators can spot a session whose confidence is dropping and intervene before it becomes a security incident.

E. Model Engine (AI Pulse Card)

Circular gauge — 99.2% health with "healthy" label and "v2.4.1" version.
3 sub-metrics: 1.24k predictions/second, 12ms p50 latency, 38ms p99 latency.
Link: "Open Live AI Monitor →" navigates to /admin/ai/live.
Model health at a glance. The p50/p99 latency split is critical — high p99 means some users are experiencing slow auth decisions. The version number ensures operators know which model is in production.

F. Decision Flow (PipelineFlow)

PipelineFlow — visual representation of the inference pipeline stages: Feature Extraction → LightGBM Scoring → One-Class SVM → Threshold Decision → Action (Allow/Challenge/Deny). Shows which stage is currently active (stage 3 = SVM). "all stages green" status.
Operations transparency into the AI pipeline. If a stage goes red, operators know exactly where the failure is without digging through logs.

G. Open Incidents (Attention Lane)

List of Incident entries from useAdminIncidents(): ID, severity badge (critical/alert/watch/info) with color coding, source system, age, title, "Triage" action button. Top 5 shown, link to full list.
Incident response queue. Severity color coding follows ITIL standards (critical=red, alert=orange, watch=yellow, info=blue). The triage button is the entry point for incident management workflow.

H. System Health

4 resource gauges with icons and progress bars:
  • CPU — 38% utilization. Icon: Cpu.
  • Memory — 62% utilization. Icon: MemoryStick.
  • Disk — 41% utilization. Icon: HardDrive.
  • Inference — 71% utilization. Icon: Activity.
Color gradient: green below 75%, red above 75%. Link to full infrastructure page.
DevOps health monitoring. Inference utilization is separated from general CPU because it's the most critical metric — high inference load means the behavioral auth pipeline is saturated.

Backend Services & Data Flow

How Data Gets to the UI

The full data pipeline
  MongoDB Atlas (Beanie ODM)
       ↓
  Backend Service (FastAPI + Pydantic v2)
       ↓  serialization_alias → camelCase JSON
  React HTTP Adapter (fetch + silent token refresh)
       ↓  TypeScript contract types
  React Query Hook (caching, retry, stale-while-revalidate)
       ↓  useQuery / useMutation
  React Component (loading → data → empty → error states)
Every layer is typed and validated. MongoDB documents → Pydantic schemas → camelCase JSON → TypeScript contracts → React hooks → UI components. No data goes through untyped channels. The serialization_alias system ensures Python snake_case fields become JavaScript camelCase without manual transformation.
