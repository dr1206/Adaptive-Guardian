1. Project Overview & Vision

1.1 The Problem

Traditional authentication (passwords, PINs, OTPs) is a single-point gate. Once a user logs in, the system has zero ability to verify that the same legitimate user is still at the keyboard. This creates an enormous attack surface:

  • Session hijacking — an attacker takes over an already-authenticated session
  • Insider threats — legitimate credentials used by unauthorized actors
  • Device theft — post-login device compromise with full session access
  • Coercion — a legitimate user forced to authenticate under duress

Identity theft losses reached approximately USD 43 billion annually according to industry reports. The fundamental flaw is architectural: authentication happens once, then trust is assumed indefinitely.

1.2 Our Solution

A Secure Adaptive Multimodal Continuous Authentication System that silently verifies user identity throughout the entire session by analyzing how they interact with their keyboard and mouse — behavioral patterns that are unique, difficult to forge, and impossible to steal.

The system extracts behavioral features (keystroke hold time, flight time, typing rhythm, cursor speed, trajectory curvature, click patterns), selects the most discriminative features using mRMR, balances training data with SMOTE, and deploys a hybrid model (LightGBM classifier + One-Class SVM anomaly detector) that continuously scores user behavior against their stored profile. When anomalies are detected, step-up authentication (OTP) is triggered. Critically, the user's behavioral profile adapts over time through a sliding-window update mechanism, accommodating natural evolution in typing speed, new keyboards, fatigue, and aging.

2.2 Analysis

FinTech Web Application (Score: 9.15/10) — RECOMMENDED

The FinTech domain is the optimal delivery vehicle for six reasons:

  1. Natural behavioral signal richness. Banking workflows involve both heavy typing (beneficiary names, amounts, passwords, notes) and dense mouse interaction (navigation, form-filling). Dual-modality richness for high-confidence authentication.
  2. Security expectations align. FinTech users expect and tolerate security friction (OTP challenges, session timeouts). Anomaly-triggered re-authentication operates without harming UX.
  3. Regulatory tailwinds. RBI guidelines, PSD2/SCA in Europe, and FFIEC guidance push toward continuous risk-based authentication.
  4. Clear demo narrative. "A banking session where the system silently verifies the user and only challenges when behavior deviates."
  5. Resume differentiation. A FinTech security product with behavioral ML and SHAP explainability is a strong portfolio piece.
  6. Scale path. Containerized, cloud-deployable, and demonstrable with real user data — production-grade by design.

Why not the alternatives:

  • Enterprise SSO: Requires integration with identity providers (Okta, Azure AD), adding deployment complexity.
  • Standalone Desktop Agent: Native OS listeners are harder to demonstrate and limit cross-platform reach.
  • Mobile Banking App: Mobile behavioral biometrics is a different research track (sensor-based). Our literature foundation is desktop-focused.
  • Academic Demo Portal: Sacrifices industry relevance and resume value.

2.3 Recommended Execution

Build the system as a FinTech Web Application — a realistic banking dashboard (accounts, transfers, transaction history, beneficiary management) that embeds behavioral data collection transparently. The core deliverable is the continuous authentication engine; the banking UI is the vehicle, not the product.

5.2 Why This Stack

FastAPI over Flask/Django: The project report mentions Flask, but FastAPI offers native async (critical for WebSocket streaming), automatic OpenAPI docs, and better concurrent event-ingestion performance.

MongoDB over PostgreSQL: Behavioral event data is heterogeneous — keystroke events differ from mouse events. MongoDB's flexible document model naturally accommodates this without complex EAV tables.

Why NOT TensorFlow/PyTorch: Literature shows gradient-boosted trees and kernel methods match or exceed deep learning for tabular behavioral features with smaller datasets (~50 users, ~20K samples). Deep learning adds complexity and GPU dependency without proportional gains at this scale.

6.2 mRMR Feature Selection

Reduces ~120 extracted features to 36 most discriminative features.

Python 
import numpy as np
from sklearn.feature_selection import mutual_info_classif

def mrmr_feature_selection(X, y, k=36):
    """Min Redundancy Max Relevance — selects k best features."""
    n_features = X.shape[1]
    remaining = set(range(n_features))
    selected = []
    mi_scores = mutual_info_classif(X, y, random_state=42)
    first = np.argmax(mi_scores)
    selected.append(first); remaining.remove(first)

    for _ in range(k - 1):
        best_score, best_feature = -np.inf, None
        for f in remaining:
            relevance = mi_scores[f]
            redundancy = np.mean([
                np.abs(np.corrcoef(X[:, f], X[:, s])[0, 1])
                for s in selected
            ])
            score = relevance - redundancy
            if score > best_score:
                best_score, best_feature = score, f
        selected.append(best_feature)
        remaining.remove(best_feature)
    return selected

Why 36: Wang & Hou (2024) and Krishnamoorthy et al. (2018) found ~30–40 features represent the knee of the relevance-redundancy curve.

from imblearn.over_sampling import SMOTE
from collections import Counter

def balance_dataset(X, y, random_state=42):
    print(f"Before SMOTE: {Counter(y)}")  # e.g., {0: 50, 1: 2200}
    smote = SMOTE(sampling_strategy='auto', k_neighbors=5, random_state=random_state)
    X_bal, y_bal = smote.fit_resample(X, y)
    print(f"After SMOTE:  {Counter(y_bal)}")  # {0: 2200, 1: 2200}
    return X_bal, y_bal

import lightgbm as lgb

def train_lightgbm(X_train, y_train, X_val, y_val):
    params = {
        'objective': 'binary', 'metric': 'binary_logloss',
        'boosting_type': 'gbdt', 'num_leaves': 31,
        'learning_rate': 0.05, 'feature_fraction': 0.8,
        'bagging_fraction': 0.8, 'bagging_freq': 5,
        'min_data_in_leaf': 20, 'lambda_l1': 0.1,
        'lambda_l2': 0.1, 'seed': 42, 'verbose': -1,
    }
    train_data = lgb.Dataset(X_train, label=y_train)
    val_data = lgb.Dataset(X_val, label=y_val, reference=train_data)
    model = lgb.train(params, train_data, num_boost_round=500,
        valid_sets=[val_data],
        callbacks=[lgb.early_stopping(30), lgb.log_evaluation(50)])
    return model

from sklearn.svm import OneClassSVM
from sklearn.preprocessing import StandardScaler

def train_ocsvm(X_genuine_only, nu=0.05, gamma='scale'):
    scaler = StandardScaler()
    X_scaled = scaler.fit_transform(X_genuine_only)
    model = OneClassSVM(kernel='rbf', nu=nu, gamma=gamma, tol=1e-3)
    model.fit(X_scaled)
    return model, scaler

6.6 Adaptive Profile Update

Python 
class AdaptiveProfileManager:
    def __init__(self, max_windows=500, retrain_interval=100):
        self.profile_windows = deque(maxlen=max_windows)
        self.retrain_counter = 0
        self.retrain_interval = retrain_interval

    def add_window(self, feature_vector, confidence_score, threshold=0.90):
        if confidence_score >= threshold:
            self.profile_windows.append(feature_vector)
            self.retrain_counter += 1

    def should_retrain(self):
        return self.retrain_counter >= self.retrain_interval

    def get_training_data(self):
        return np.array(self.profile_windows)

9.2 Behavioral Data Collector (Core Module)

TypeScript 
// collector/BehavioralCollector.ts
interface KeystrokeEvent {
  key: string; pressTime: number; releaseTime: number; holdTime: number;
}

class BehavioralCollector {
  private keystrokeBuffer: KeystrokeEvent[] = [];
  private mouseBuffer: MouseEvent[] = [];
  private pressTimes: Map = new Map();
  private windowDuration = 60000; // 60 seconds
  private sessionId: string;

  constructor(sessionId: string, wsUrl: string) {
    this.sessionId = sessionId;
    this.connectWebSocket(wsUrl);
    this.attachListeners();
    this.startWindowTimer();
  }

  private attachListeners(): void {
    document.addEventListener('keydown', this.onKeyDown.bind(this));
    document.addEventListener('keyup', this.onKeyUp.bind(this));
    document.addEventListener('mousemove', this.onMouseMove.bind(this));
    document.addEventListener('click', this.onClick.bind(this));
    document.addEventListener('wheel', this.onScroll.bind(this));
  }

  private onKeyUp(e: KeyboardEvent): void {
    const t = performance.now() / 1000;
    const pressTime = this.pressTimes.get(e.key);
    if (pressTime) {
      this.keystrokeBuffer.push({
        key: e.key, pressTime, releaseTime: t, holdTime: t - pressTime
      });
    }
  }

  private onMouseMove(e: MouseEvent): void {
    const t = performance.now() / 1000;
    let speed = 0;
    if (this.lastMousePos && this.lastMouseTime) {
      const dx = e.clientX - this.lastMousePos[0];
      const dy = e.clientY - this.lastMousePos[1];
      const dt = t - this.lastMouseTime;
      speed = dt > 0 ? Math.sqrt(dx*dx + dy*dy) / dt : 0;
    }
    this.mouseBuffer.push({ x: e.clientX, y: e.clientY, timestamp: t, speed, eventType: 'move' });
    this.lastMousePos = [e.clientX, e.clientY];
    this.lastMouseTime = t;
  }
  // ... onClick, onScroll, startWindowTimer, flushWindow, connectWebSocket
}

9.4 UX Principles

  1. Zero-friction collection. Behavioral listeners operate passively — no "collecting data" UI.

  4. Progressive enhancement. Password-only fallback; continuous auth is an additional layer, not a gate.

def evaluate_model(model, X_test, y_test) -> dict:
    from sklearn.metrics import (
        accuracy_score, precision_score, recall_score,
        f1_score, roc_auc_score, confusion_matrix
    )
    y_pred = model.predict(X_test)
    y_proba = model.predict_proba(X_test)[:, 1]
    tn, fp, fn, tp = confusion_matrix(y_test, y_pred).ravel()
    far = fp / (fp + tn)      # False Acceptance Rate
    frr = fn / (fn + tp)      # False Rejection Rate
    eer = compute_eer(y_test, y_proba)
    return {
        "accuracy": accuracy_score(y_test, y_pred),
        "precision": precision_score(y_test, y_pred),
        "recall": recall_score(y_test, y_pred),
        "f1_score": f1_score(y_test, y_pred),
        "g_mean": np.sqrt(tp/(tp+fn) * tn/(tn+fp)),
        "auc_roc": roc_auc_score(y_test, y_proba),
        "far": far, "frr": frr, "eer": eer,
    }

13.2 Privacy Considerations

The behavioral data collected is not keystroke logging — no typed content is stored, only timing metadata and key identifiers. This is consistent with academic best practices (Baig et al. 2023, Abuhamad et al. 2020). Homomorphic encryption for scoring on encrypted vectors is identified as future work.

17. Future Scope & Research Directions

17.1 Near-Term Enhancements (Post-Project)

  1. Privacy-Preserving (Homomorphic Encryption). Paillier cryptosystem for scoring on encrypted vectors (Baig et al. 2023).
  2. Deep Learning for Raw Temporal Modeling. CNN+GRU architecture learning from raw keystroke/mouse sequences (Kasprowski et al. 2022, Wycislik et al. 2024).
  3. SIURUA — Scene-Irrelated Features. Multiple Kernel Learning robust to what the user is doing (Wang et al. 2022).
  4. Coercion Detection via LLM. LLM-assisted multimodal pipeline analyzing stress/coercion indicators (Almehmadi 2025).

17.2 Research Directions

  1. Acoustic Keystroke Biometrics (SoundAuth). Fusion of keyboard acoustics + timing dynamics. 98.44% accuracy, 0.1% FAR (Liu et al. 2025).
  2. Cross-Device Behavioral Transfer. Domain adaptation from desktop keyboard/mouse to laptop touchpad.
  3. Federated Learning. Train on-device; only encrypted gradient updates to central server.
  4. Physiological-Behavioral Fusion. Keystroke timing + HRV from webcam PPG for multi-factor CA.
  5. Adversarial Robustness. Study and defend against synthetic event injection and replay attacks.
  6. Longitudinal Behavioral Study. 6–12 month deployment to study real drift patterns.
